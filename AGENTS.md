# Moraine

A personal workspace for building projects, storing documents, and running agentic AI workflows.

## Purpose

- **Projects**: Develop software projects across various domains.
- **Documents**: Store and manage documents and reference materials.
- **AI/Agentic Workflows**: Use your agent harness for research, chat, coding, and agent-based automation.
- **Memory System**: Persistent agent memory for context retention across sessions.
- **Custom Agent Ecosystem**: Skills, packs, and plugins for extending agent capabilities.

## Directory map

| Directory | Purpose | When to read | When to write |
|-----------|---------|--------------|---------------|
| `repos/` | External project repos — each subdirectory is its own git repo, registered as pointers | When working on a project that lives here | Clone with `moraine repos restore`; register repos in `repos/README.md` |
| `memory/` | Agent session summaries, handoffs, and periodic reviews | At the start of every session and when catching up on past work | At the end of every session via `session-handoff` |
| `memory/index.md` | Entry point: active projects, open threads, recent decisions | **First file to read** each session | Updated by `session-handoff` at wrap-up |
| `memory/sessions/` | Per-session summaries and handoffs | When resuming a specific thread or reviewing recent work | Written by `session-handoff` at wrap-up |
| `memory/reviews/` | Periodic pattern analysis from past sessions | When deciding what to automate next | Written by review skills at wrap-up |
| `memory/staging/` | Short-term working memory — transient notes that persist across sessions | At session startup and when catching up on recent thoughts | During sessions; organized by date (`YYYY-MM-DD.md`) |
| `memory/.index/` | Derived search indexes (gitignored) | Never read directly — used by `session-search` | Auto-generated by `scripts/workspace/session-index.py` |
| `scripts/workspace/` | Core workspace scripts (validation, health, memory, search, sync) | When modifying workspace tooling | When changing core tooling |
| `wiki/` | PARA vault for human knowledge management | When researching a topic or linking to existing knowledge | When creating notes or organizing knowledge |
| `wiki/1 Projects/` | Project top notes with YAML frontmatter + `projects.md` index | When checking project portfolio, status, or next actions | When creating or updating a project, always add/update frontmatter |
| `wiki/2 Areas/` | Ongoing responsibilities (no finish line) + `areas.md` index | When checking area-level context | When updating area top notes |
| `artifacts/` | Research, architecture docs, design plans | When planning or understanding design decisions | When producing research or architecture output |
| `docs/` | Maintenance and onboarding guides (upstream sync, first session) | When a guide exists for the task at hand | Rarely — upstream owns these |
| `.agents/skills/` | Core skills as real folders, plus one symlink per enabled pack skill | Automatically discovered by agents | Never by hand — `moraine sync` writes the symlinks; add skills with `create-skill` |
| `packs/` | Opt-in packs, each self-contained: `pack.yaml`, skills, scripts, jobs | When a task touches a pack's domain | Upstream owns shipped packs; `packs/local/` is yours |
| `moraine.yaml` | Which harnesses and packs this workspace enables | When a pack's skill or server seems missing | You — `moraine packs enable/disable` edits it, then run `moraine sync` |

## Session start and wrap-up

At session start, read `memory/index.md`, then `packs/local/AGENTS.md` if it exists. Enabled packs are listed in `moraine.yaml`; before using a pack's skills, read `packs/<name>/AGENTS.md`.

At wrap-up, run the `session-handoff` skill: it writes `memory/sessions/`, updates `memory/index.md`, and commits the memory stores.

## Conventions

- The wiki (`wiki/`) uses PARA for human knowledge management. The memory system (`memory/`) is for agent session context. Agents write to `memory/`, humans write to `wiki/`.
- **Anti-slop checklist (milestone/feature work — not tight fix loops or review-apply passes).** While writing code, avoid the patterns SlopCodeBench showed agents overproduce: abnormal defensive checks a human wouldn't add; casts or guards that fight the type system; single-use variables that just rename an expression; comments restating what the code says; trivial one-line wrappers; nesting depth ≥ 4; if/elif ladders ≥ 3 that should be dispatch; helper-method sprawl (single-call helpers that exist to make the diff look organized). Write code you wouldn't flag against this list.
- Skills live in flat `<name>/SKILL.md` folders: core in `.agents/skills/`, everything else in `packs/<pack>/skills/`, following the harness's naming rules. Enabled packs are listed in `moraine.yaml`; `python3 scripts/moraine sync` links their skills into `.agents/skills/`. Skills you write go in `packs/local/skills/`.
- Session summaries go in `memory/sessions/`, handoffs are optional.
- `wiki/0 Inbox/00 Scratchpad.md` is the human scratchpad — agents must never write to it.
- `memory/`, `wiki/`, and `artifacts/` are committed to git. Never write customer data, PII, credentials, incident details, or NDA material into them; keep secrets in `.env` (gitignored) and reference them by name.
- **Moraine is for personal workspaces.** Do not put employer-confidential code, customer data, credentials, or NDA material into it; use it for work only in an employer-approved environment. Deterministic scanning is a backstop for known secret patterns, not a way to detect confidential prose or source code — this boundary is the primary control.
- Artifacts are numbered sequentially (`01-`, `02-`, etc.) and must include a Table of Contents with anchor links to each section. Start from `artifacts/_TEMPLATE.md`. Allocate the number with `python scripts/workspace/next-artifact.py --claim <slug>` — never hand-pick it from `ls`, because two sessions running at once will otherwise claim the same number.

## Health checks

Deterministic scripts in `scripts/workspace/`. All flag-only (never modify memory) except where noted.

| Script | What it checks | When to run |
|--------|----------------|-------------|
| `validate.py` | Skills frontmatter, wikilinks, project top notes, manifests, structural rules | After editing skills, the wiki, or manifests |
| `health-check.py` | Core tools, MCP config shape, sync drift | On demand |
| `memory-audit.py` | Decision pruning, repo drift, stalled projects, past-due threads, review cadence, stale staging (>14d) | Weekly |
| `project-status.py` | Last session activity per project (`--stale-only --days N`) | Session start when choosing work |
| `moraine repos check` | The `repos/` pointer registry vs disk: missing repos, unregistered clones, remote drift | After adding/removing repos |
| `agent-eval.py` | Golden-task eval harness (core tasks, plus any contributed by enabled packs) | After changing workspace tooling |
| `prune-decisions.py` | Archives old "Recent decisions" blocks from `memory/index.md` (`--prune` modifies) | When flagged by memory-audit |
